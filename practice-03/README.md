## Организация кода

- `src/task-service.js` — прикладная логика (класс `TaskService`, перенесён из ПР2 без изменений).
- `src/task-selectors.js` — класс `TaskSelectors` со статическим методом `getVisibleTasks(tasks, filter)`; хранит **только** правило отбора по фильтру, состояние не хранит.
- `src/task-view.js` — класс `TaskView`: `createTaskElement` строит одну карточку `li.task-card`, `renderTaskList` заменяет дочерние элементы контейнера списка (сам `<ul>` не пересоздаётся — на нём висит делегированный обработчик), `renderSummary` и `renderEmptyState` обновляют сводку и пустое состояние. DOM создаётся и читается, состояние приложения здесь не меняется.
- `src/main.js` — класс `App`: хранит `currentTasks`/`currentFilter` (единственное место с состоянием), методы `renderApp()` (собирает видимые задачи и вызывает `task-view.js`), `handleTaskListClick`/`handleFilterClick` (делегированные обработчики, назначены один раз на `#task-list`/`#task-filters`) и готовую `restoreTaskFocus`. Событие обрабатывается в `App`, сводка вычисляется в `task-service.js` через `getTaskStats`, видимый список — в `task-selectors.js`.

## Отладка и клавиатура

Точка останова ставилась на первой строке `handleTaskListClick` (`const button = event.target.closest(...)`). При клике по `.action-label` внутри кнопки `toggle` карточки `id=4`: `event.target` — сам `<span class="action-label">`, `event.currentTarget` — `#task-list` (обработчик делегирован на список, а не на кнопку), `card.dataset.taskId` — строка `"4"`, `Number(card.dataset.taskId)` — число `4`, `button.dataset.action` — `"toggle"`; итог сервисного вызова — `setTaskCompleted(currentTasks, 4, true)` → `{ ok: true, tasks: [...] }`.

Проверка клавиатуры: кнопки — обычные `<button type="button">`, поэтому `Tab` переводит фокус между ними в порядке разметки, а `Enter`/`Space` активируют кнопку так же, как клик мыши (стандартное поведение элемента `button`, отдельного кода не потребовалось). После переключения статуса или удаления фокус возвращается на ту же кнопку той же карточки (если она осталась) либо на кнопку активного фильтра — это уже реализовано в `restoreTaskFocus` и вызывается из `handleTaskListClick` после `renderApp()`.

Отдельно проверены отказы по некорректному `id` карточки: `data-task-id="777"` (несуществующий, но корректный числовой id) и `data-task-id="4abc"` (нечисловая строка) — в обоих случаях `#operation-message` получает непустой текст ошибки, а `currentTasks` не меняется (сводка после возврата к фильтру «Все» точно совпадает с исходной).

## Вывод

Логика фильтрации и построения карточек (`task-selectors.js`, `task-view.js`) переиспользует проверенный в ПР2 `task-service.js` и не хранит состояния — единственное изменяемое состояние (`currentTasks`, `currentFilter`) сосредоточено в классе `App` из `main.js`. Ключевое различие, которое подтвердили проверки: клик по кнопке меняет **данные** через вызов функции ПР2 (`setTaskCompleted`/`removeTask`), и только после успешного результата перерисовывается **DOM** через `renderApp()` — прямое изменение разметки в обработчике клика не используется нигде, поэтому повторная загрузка или фильтрация никогда не расходится с реальным состоянием задач.
