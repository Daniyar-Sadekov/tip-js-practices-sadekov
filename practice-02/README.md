## 4. Модель и распределение ответственности

- `src/data.js` — только данные: `demoTasks`, `variantNumber = 7`, `variantTasks`.
- `src/task-service.js` — вся прикладная логика оформлена в виде класса `TaskService` со статическими методами (`createTask`, `findTaskById`, `getPendingTasks`, `getTaskTitles`, `getTaskStats`, `addTask`, `setTaskCompleted`, `renameTask`, `removeTask`) и двумя приватными помощниками (`_isValidId`, `_normalizeTitle`, `_isValidPriority`) — чтобы не дублировать проверки id/названия/приоритета между операциями. Наружу модуль отдаёт **именованные функции-обёртки** с теми же именами и сигнатурами, которые вызывает `checks.js` и `main.js` — контракт методички (`import { createTask, ... }`) при этом не нарушается.
- `src/main.js` — класс `ScenarioRunner` (метод `logSummary` для вывода сводки, `apply` для применения результата операции) прогоняет общий сценарий (`demoTasks`) и сценарий варианта (`variantTasks`); вычисления не дублируются, всё идёт через `task-service.js`.
- Деструктуризация используется, например, в `getTaskStats`/`logSummary`: `const { total, completed, pending, progress } = getTaskStats(this.tasks);`.
