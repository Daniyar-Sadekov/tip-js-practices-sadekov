## Реализация

- `src/task-validation.js` — `validateTaskInput(value, { partial, categoryIds })`: проверяет, что тело — обычный объект (не `null`, не массив, не примитив), использует словарь ошибок `Object.create(null)` (защита от ключа `__proto__`), запрещает передачу `id` и неизвестных полей, проверяет `title` (строка 1–100 символов после `trim()`), `priority`, `categoryId` (и `completed` только для `PATCH`). При наличии ошибок выбрасывает `ApiError(400, 'VALIDATION_ERROR', ..., details)` со всеми ошибками сразу — хранилище при этом не изменяется.
- `src/store.js` — хранит задачи в памяти, назначает монотонно возрастающий `id` (после удаления `id` не переиспользуется), в `PATCH` обновляет только переданные поля, сохраняя остальные, и всегда возвращает копии объектов.
- `src/write-routes.js` — маршруты `POST /tasks` (`201 Created` + заголовок `Location`), `PATCH /tasks/:id` (`200 OK`), `DELETE /tasks/:id` (`204 No Content`).
- `src/json-body.js` и `src/errors.js` — проверка `Content-Type: application/json`, лимита размера тела, разбор JSON (`INVALID_JSON`) и единый `errorHandler`, преобразующий `ApiError` в JSON-ответ с нужным HTTP-статусом.

## Контракт

- `POST /api/tasks` → `201 Created`, заголовок `Location: /api/tasks/<id>`, тело `{"data": { ... }}`.
- `PATCH /api/tasks/:id` → `200 OK`, тело `{"data": { ... }}` с обновлённой задачей.
- `DELETE /api/tasks/:id` → `204 No Content` без тела.
- Невалидное тело (`POST` с `{"title":"   ","priority":"high","categoryId":2}`) → `400 Bad Request`, тело `{"error":{"code":"VALIDATION_ERROR","message":"Данные не прошли проверку.","details":{"title":"Название — строка от 1 до 100 символов без краевых пробелов."}}}` (зафиксировано в `kr3/screenshots/task4-post-400.png`).
- Различие `INVALID_JSON` и `VALIDATION_ERROR`: `INVALID_JSON` возникает на этапе синтаксического разбора сломанного/пустого JSON, а `VALIDATION_ERROR` — когда JSON синтаксически корректен, но нарушает прикладные правила полей.

## Исправленный дефект

Симптом: при передаче специального поля `"__proto__"` в теле JSON обычный объект `{}` для `details` может некорректно обрабатывать ключ прототипа. Исправление: словарь ошибок создаётся через `Object.create(null)`, поэтому даже ключ `"__proto__"` корректно сохраняется в `details` и отдаётся в ответе `400` (подтверждено тестом «Специальное имя `__proto__` отклоняется с details»).

## Контрольные вопросы

- **Почему серверная валидация обязательна, даже если в HTML-форме есть `required`?** Атрибуты HTML работают только в браузере и легко обходятся через DevTools, `curl`, Postman или другой клиент; только серверная валидация гарантирует целостность данных в хранилище.
- **Зачем проверять все поля до изменения хранилища?** Чтобы исключить частичное обновление и вернуть клиенту сразу все ошибки в одном ответе `400`, не оставляя данные в полуизменённом состоянии.
- **Почему после перезапуска сервера все изменения пропадают?** В ПР10 хранилище `store.js` держит данные в оперативной памяти процесса Node.js; для долговременного хранения нужна база данных (PostgreSQL в ПР11–ПР12).
