## Реализация

- `src/validation.js` — строгий разбор `query`-параметров (`parseFilters`) и числовых идентификаторов (`parseId`): проверяет белый список допустимых параметров (`ALLOWED_FILTERS`), отклоняет дубликаты query-параметров (`Array.isArray(raw)`), нормализует `completed` (`"true"`/`"false"` → `boolean`, не теряя `false`), проверяет `priority` и `categoryId`.
- `src/task-service.js` — чистая фильтрация массива задач по нормализованным фильтрам (включая регистронезависимый поиск `q`) и формирование выборки.
- `src/store.js` — хранилище исходных задач и категорий в памяти с возвратом копий.
- `src/routes.js` — маршрутизация Express (`router.get('/tasks', ...)`, `/tasks/:id`, `/categories`, `/health`) и возврат `405 Method Not Allowed` с заголовком `Allow` для неподдерживаемых методов (включая `POST`/`PATCH`/`DELETE`).
- `src/app.js` и `src/server.js` — сборка Express-приложения, порядок middleware (CORS и безопасные заголовки → маршруты → `404` для неизвестных путей → централизованный `errorHandler`) и запуск HTTP-сервера.

## Исправленный дефект

Симптом: в Express повторяющийся query-параметр (например, `?completed=true&completed=false`) приходит как массив строк, а `completed=false` при наивной проверке `if (filters.completed)` теряется. Причина: отсутствие проверки типа query и неявное приведение к boolean. Исправление: в `parseFilters` добавлена проверка `Array.isArray(raw)` (возвращает 400) и строгое сравнение `raw === 'true'` / `raw === 'false'` с хранением `null`, если фильтр не задан. Подтверждено прохождением всех 90 тестов.

## Контрольные вопросы

- **Зачем проверять неизвестные и повторяющиеся query-параметры?** Чтобы клиент сразу получил `400 Bad Request` при опечатке (например, `completd=true`), а не молча получил неотфильтрованный список.
- **Почему важен порядок middleware в Express?** Обработчики выполняются сверху вниз: заголовки CORS должны ставиться до маршрутов, `404` — после всех маршрутов, а `errorHandler` с 4 аргументами `(err, req, res, next)` — самым последним.
- **Почему `POST /api/tasks` в ПР9 возвращает `405`?** Маршрут `/api/tasks` существует, но в ПР9 поддерживает только `GET`, `HEAD` и `OPTIONS`; стандарт HTTP предписывает для неподдерживаемого метода возвращать `405` с заголовком `Allow`.
