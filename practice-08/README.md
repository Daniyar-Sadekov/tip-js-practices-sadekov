## Полученный результат

React-интерфейс из ПР7 переведён на работу с HTTP API через кастомный хук `useTaskData`. Поддерживаются асинхронная загрузка задач и категорий, серверная фильтрация, полный CRUD (`POST`, `PATCH`, `DELETE`, `reset`), отображение состояний `loading` / `ready` / `error` и раздельная обработка ошибок чтения и мутации. Изменения сохраняются в памяти учебного сервера до его перезапуска.

## Архитектура

- `src/api/api-client.js` — универсальный HTTP-клиент (`fetch`, `AbortSignal`, тайм-аут, `ApiError`, обработка `204`).
- `src/api/task-api.js` — доменные запросы и валидация ответов API.
- `src/hooks/useTaskData.js` — кастомный хук, инкапсулирующий `useEffect` загрузки, `AbortController` в cleanup, `useRef` для счётчика актуальности запросов и защиты от двойных мутаций, состояния `status` (`loading` / `ready` / `error`), `snapshot` (`tasks`, `categories`, `meta`), `error`, `pending` и `mutationError`.
- `src/App.jsx` и компоненты — чистый UI поверх данных и действий, возвращаемых хуком.

Отличие от ПР7: источником истины стал сервер API, фильтрация выполняется на сервере, а локальные синхронные мутации заменены асинхронными запросами с последующей перезагрузкой актуального снимка.

## Загрузка и изменения

- **Подавление старых ответов:** в `useEffect` на каждую загрузку создаётся `AbortController` (отменяется в функции очистки `cleanup` при смене `filters`, повторном запуске в `StrictMode` или размонтировании) и проверяется актуальность запроса через счётчик `ref` — устаревший ответ или ошибка игнорируются.
- **Блокировка повторной мутации:** синхронный флаг в `useRef` + состояние `pending` гарантируют, что два одновременных клика отправят только один запрос.
- **Разделение ошибок POST и повторного GET:** ошибка записи попадает в `mutationError` (черновик формы сохраняется, чтобы пользователь не потерял ввод), а ошибка последующего обновления списка — в `error` при сохранении последнего успешного `snapshot`.

## Контрольные вопросы

- **Зачем cleanup в `useEffect`?** Чтобы отменить незавершённый `fetch` через `AbortController.abort()` при изменении зависимостей (`filters`) или размонтировании компонента и не допустить гонки ответов.
- **Почему в консоли `true 0` и `false 2` выводятся по два раза?** В режиме разработки React `StrictMode` намеренно дважды вызывает рендер и цикл монтирования эффектов, чтобы выявить побочные эффекты без корректного cleanup.
- **Зачем нужен `useRef` рядом с `useState`?** `useRef` хранит изменяемое значение синхронно между рендерами без лишних перерисовок — идеально для блокировки двойной мутации и счётчика актуальности запросов.
