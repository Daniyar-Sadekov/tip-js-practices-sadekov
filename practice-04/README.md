## Эксперименты с формой и хранилищем

| № | До запуска: прогноз | После запуска: результат | Объяснение |
|---:|---|---|---|
| 1. Пустое обязательное поле | Браузер не отправит форму при пустом `required` | Событие `submit` блокируется нативной проверкой HTML5 | Атрибут `required` работает только в браузерной форме и не проверяет строку из пробелов. |
| 2. Название из пробелов | HTML `required` пропустит `"   "`, прикладная проверка должна отклонить | `required` пропускает, `validateTaskDraft` возвращает `ok: false` и `errors.title` | После `trim()` длина равна `0`, поэтому обязательна прикладная валидация в JS. |
| 3. Типы значений `FormData` | Все поля из `FormData` приходят как строки | `typeof draft.id === "string"`, даже для `<input type="number">` | `FormData` всегда возвращает строковые значения (или `File`), поэтому `id` преобразуется явно с проверкой целого положительного числа. |
| 4. Строка в `localStorage` и JSON | В `localStorage` хранится только строка | `setItem` сохраняет JSON-строку `{"version":1,"tasks":[...]}`, `getItem` возвращает строку | `localStorage` — хранилище пар «строка → строка», поэтому объекты и массивы сериализуются через `JSON.stringify` и восстанавливаются через `JSON.parse`. |
| 5. Повреждённый JSON | `JSON.parse` выбросит `SyntaxError` | `loadTasks` перехватывает ошибку в `try/catch` и возвращает копию `fallbackTasks` с предупреждением | Нельзя доверять внешним данным из хранилища: повреждённый JSON не должен ронять приложение. |

## Организация кода

- `src/task-service.js` — чистая прикладная логика работы со списком задач (иммутабельные операции создания, обновления, переключения статуса, удаления, подсчёта сводки).
- `src/form-validation.js` — класс `FormValidation` (`validateTaskDraft`, `_checkId`, `_checkTitle`, `_checkPriority`), проверяет и нормализует черновик формы в режимах создания и редактирования.
- `src/task-storage.js` — класс `TaskStorage` (`saveTasks`, `loadTasks`, `resetTasks`, `isValidTaskList`), отвечает за сериализацию JSON с версией `STORAGE_VERSION = 1`, валидацию схемы при чтении и безопасный откат к `fallbackTasks`.
- `src/task-view.js` — построение DOM карточек, сводки и пустого состояния без хранения состояния.
- `src/main.js` — класс `App`: связывает состояние (`currentTasks`, `currentFilter`, `editingId`), форму, делегирование событий и вызовы `loadTasks`/`saveTasks`.

Объект `storage` передаётся в функции хранения аргументом (внедрение зависимости), чтобы модуль не зависел жёстко от глобального `window.localStorage` и легко тестировался в Node.js с подменным хранилищем. Данные после `JSON.parse` проверяются по версии и схеме (`isValidTaskList`), потому что запись в `localStorage` могла быть изменена вручную, повреждена или остаться от другой версии приложения.

| Случай | Ожидание | Фактический результат | Итог |

## Отладка и клавиатура

В `handleFormSubmit` сырой объект `draft` содержит строковые значения полей формы; `validateTaskDraft` возвращает `{ ok: true, value }` с числовым `id` и обрезанным `title`, после чего `addTask`/`updateTask` возвращает новый массив `tasks`, а `saveTasks` сериализует `{ version: 1, tasks }` в JSON-строку. Элементы формы и кнопки карточек доступны с клавиатуры (`Tab`, `Enter`, `Space`), при входе в редактирование и отмене фокус переводится предсказуемо.
