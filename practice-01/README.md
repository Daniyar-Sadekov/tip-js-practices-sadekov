## 4. Задание 1 — два способа запуска

Файл `js/hello.js` запускался и через Node.js, и в браузере (через `index.html`).

Фактический вывод в Node.js:

```
Студент: Садеков Данияр Жигангисович
Группа: ЭФБО-06-25
Практическая работа: 1
JavaScript успешно запущен
Тип document: undefined
```

В браузере вывод в Console идентичен первым четырём строкам, но последняя строка отличается: `Тип document: object`, а не `undefined`. Причина — в браузере скрипт выполняется в контексте открытой HTML-страницы, поэтому глобальный объект `document` существует и доступен; при обычном запуске файла через `node` HTML-страница не создаётся, DOM отсутствует, и `document` — необъявленная переменная (`typeof` для неё возвращает `"undefined"`, а не ошибку). Результат появляется **только в консоли**, на самой странице текст не отображается.

## 5. Задание 2 — типы и преобразования

| Выражение | Ожидание до запуска | Фактическое значение | Тип результата | Объяснение |
|---|---|---|---|---|
| `"8" + 2` | `"82"` (конкатенация) | `82` | `string` | Один из операндов `+` — строка, поэтому оператор выполняет конкатенацию, а не сложение. |
| `"8" - 2` | `6` | `6` | `number` | У `-` нет строкового смысла операции, поэтому строка приводится к числу перед вычитанием. |
| `Number("8") + 2` | `10` | `10` | `number` | Явное приведение строки к числу через `Number()`, затем обычное сложение. |
| `"12" > "3"` | `false` (строковое сравнение) | `false` | `boolean` | Сравниваются как строки посимвольно: `"1" < "3"`, поэтому `"12"` оказывается «меньше» `"3"`. |
| `12 === "12"` | `false` | `false` | `boolean` | `===` не приводит типы; число и строка — разные типы. |
| `Number("")` | `0` | `0` | `number` | Пустая строка по правилам `Number()` преобразуется в `0`, а не в `NaN`. |
| `Number("text")` | `NaN` | `NaN` | `number` | Строка не является числовой записью, результат — `NaN`, тип которого всё равно `number`. |
| `Boolean("false")` | `true` | `true` | `boolean` | Любая непустая строка приводится к `true`, включая текст `"false"` — текст не интерпретируется как команда. |
| `typeof null` | `"object"` | `object` | `string` | Историческая особенность JS: `null` — примитив, но `typeof` для него ошибочно возвращает `"object"`. |
| `typeof NaN` | `"number"` | `number` | `string` | `NaN` относится к типу `number`, хотя обозначает «не число». |

## 7. Отладка (`debug.js`)

**Исходный (ошибочный) вариант** давал:

```
Выполнено: 32
Осталось: -24
Контрольная сумма: 6
```

| Ошибка | Что наблюдалось | Причина | Исправление | Результат после исправления |
|---|---|---|---|---|
| Обработка количества задач | `Выполнено: 32`, `Осталось: -24` вместо `5` и `3` | `completedText + additionalText` — конкатенация строк `"3"+"2"="32"`, а не сложение чисел; `plannedText - "32"` даёт `-24` | Обе строки явно приведены к числу через `Number()` перед сложением/вычитанием | `Выполнено: 5`, `Осталось: 3` |
| Граница цикла | `Контрольная сумма: 6` вместо `10` | Условие `taskNumber < 4` не включало последнюю, четвёртую итерацию (`1+2+3`) | Условие заменено на `taskNumber <= 4` | `Контрольная сумма: 10` |

**Порядок отладки в DevTools (Chromium):** в `index.html` временно подключался `./js/debug.js`; в DevTools → **Sources** открывался `debug.js`, точка останова ставилась на строке вычисления `completedTotal`. После перезагрузки страницы и остановки на брейкпоинте в панели **Scope** проверялись значения и типы `completedText` (`"3"`, `string`) и `additionalText` (`"2"`, `string`). Через **Step over** выполнялась строка вычисления — `completedTotal` до исправления оказывался строкой `"32"`, что и указывало на конкатенацию вместо сложения. Аналогично точка останова ставилась внутри цикла для отслеживания `taskNumber` и `controlSum` до последней итерации.

Скриншот `screenshots/debug-breakpoint.png` сделан: DevTools остановлен на точке останова в `debug.js:17`, панель Scope показывает `additionalText: "2"`, `completedText: "3"`, `completedTotal` — ещё не вычислен, `plannedText: "8"` — то есть в точности состояние до вычисления суммы, которое и описано выше.
